身份 / 交互 / 语义 三分工

§1.6 · 判据：看到红色时，该想到"华为鲲鹏"还是"出事了"？
Kunpeng 红#ED1C24 身份 —— splash 字标、顶栏迷你标识、NEW 新增标。强调 / 选中 / 焦点 / 语义 / 任何数据可视化
品牌蓝#0077FF 交互 —— 选中、焦点、当前对象、进度、主按钮。只做填充 / 边框 / 焦点底色，不用于文本

错误红#FF4B7B 语义 —— 失败、Critical、删除行。品牌表达
success#04D793 ✓ 完成 / 通过
warning#FFAA3B ⚠ 风险 / 待重启 / 非致命异常

域色映射 · 800 → 300

§1.6 · 蓝专属品牌，数据色从非蓝取；copy-blue 已退役（色相差 7°）
CPUub-green
NPU / GPUl0a-violet
Mem / HBMaccum-orange
Net / IOmte-amber

色阶定身份，档位定强度。同一个观测对象在任何页面都是同一个色相；"多忙"由 800→300 的档位表达，不由换色相表达。

三条用色纪律

评审时直接拿来当判据
  • ✓形状层分离，比调色相更可靠。语义色只上字符与短文本（✓ ⚠ ✕、状态标签），永不上色块；数据色阶只上色块与点阵（█▓▒░ ⣿），永不上文字。有了它，即使 warning 35° 与 accum-orange 25° 色相接近也不会误读。
  • ✕语义色不参与数据可视化。一个 90% 的 CPU 利用率本身不是"错误"——它该用顺序色阶的最亮档，而不是 danger 红。只有当 AI 判定它构成问题时，才由 P26 标注层叠加 danger 色的描边与角标。把"数据"和"结论"用不同的颜色系统表达，是这套规范里最重要的一条用色纪律。
  • ✓强调色配额：蓝 = 当前对象，或当前唯一推荐的动作。其余一律中性。第一版把蓝铺到十几处，结果蓝不再指向任何东西。评审判据：遮住所有蓝色，还能说清"我现在选中的是什么"吗？能，说明蓝铺多了。

Radius · Spacing · Motion

§3 §4 §5 · 圆角 = 浮起，其余一律直角
维度规则
Radius5 档塌缩为 2 档：┌┐└┘ 直角给表格 / 内嵌块 / 工具栏，╭╮╰╯ 圆角给主面板 / 浮层 / 卡片。Web 侧对应 0 / 2px / 4px
Spacing单元格非正方（约 1:2），单轴间距拆成 space-x（列）与 space-y（行）双轴；代码里禁止裸数字 padding
Elevation终端无阴影 → 用边框强度 + 表面步进表达层级；模态浮起靠把底层整体压暗一档
Motion@30fps：fast 3 帧 · base 6 帧 · slow 10 帧。动效只服务于功能，禁止常驻装饰动画与假进度条；RTT > 80ms 自动关过渡、spinner 降到 4fps
Typography六级字号塌缩为一级 → 层级改由粗细 + 色阶 + 大写字距 + 缩进编码；CJK 标题不做全大写，只保留字距

Chrome 层 vs Canvas 层

§0.5 · 整套设计的分界线
层包含渲染方式必须具备
Chrome
结构		 Header · Dock（任务 / 工程树 / 工具）· Tab Bar · 状态栏 · 浮层 · 列表 · 表单 · 命令面板 真 UI 组件
Textual Widget + TCSS		 表面层级 · 边框强度 · 圆角 · hover / selected / focus / disabled 四态 · 图标 · 徽标计数 · 缩进引导线 · 滚动条指示
Canvas
读数		 Braille 曲线 · 热力网格 · Trace 密度带 · Gauge / Sparkline · 散点 · diff · 日志 · 代码 字符网格
Rich renderable		 渲染分层 T1–T3 · 域色映射 · 顺序 / 分类色阶纪律 · 等宽对齐

判断标准就一句：这块内容是「结构」还是「读数」？用户在这里做的是选择 / 导航 / 切换 / 确认 → Chrome 层，用组件，需要状态表达；做的是看数值 / 比大小 / 找异常 → Canvas 层，用字符，需要密度与对齐。反过来数据区也不能用组件——64 核热力网格如果用 64 个 widget，密度、对齐、性能全都做不到。
