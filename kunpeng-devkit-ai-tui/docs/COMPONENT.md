## 3. 图表原语库

> 实现见 [`../app/devkitai/render/`](../app/devkitai/render/)，活样本跑 `python -m devkitai gallery`。
> 规范写着每种图长什么样，但字符图好不好使只有渲染出来才知道——画廊页就是这一节的 preview gate。

图元不按名字排，按**回答什么问题**分组。选图之前先问自己在回答哪个问题，
选错组的图画得再好看也读不出结论。

| 组 | 问题 | 图元 | 渲染层 | 降级到 |
|---|---|---|---|---|
| **比大小** | 谁比谁大 | Metric Bar · 排行 · 多列 · Before/After | T1 | T0 数值 |
| **看趋势** | 怎么走的 | 折线 · 面积 · Sparkline · 双向面积 | T2 | T1 Sparkline → T0 当前值 + 峰值 |
| **找位置** | 在哪儿 / 谁在等谁 | 散点 · 火焰图 · 泳道 Timeline | T2 / T1 | T1 块字符 |
| **看余量** | 还剩多少 | 水位 · 进度 · 分段 | T1 | T0 百分比 |
| **读单值** | 现在多少 | 像素数字 · 数图（stat tile） | T1 | T0 常规数字 |
| **看分布** | 热点在哪 | 热力网格 | T3 | T1 灰阶 + `░▒▓█` |

### 3.0 三条贯穿全族的规则

**① 八分之一格精度是地基。** 垂直方向有 `▁▂▃▄▅▆▇█`，水平方向同样有一套
`▏▎▍▌▋▊▉█`。一个 10 格宽的 bar 因此能表达 80 档而不是 10 档——**没有它，
82% 和 85% 画出来一模一样**，而「兼容性 82%」这种数字恰恰是拿来做判断的。

**② 并置的图必须共用量程。** 多列条形、多系列折线、Before/After、双向面积——
分别归一化会让每条都填满画布，看着都一样忙。而并置的全部意义就是比较。

**③ 画不下的东西要显式说，不能悄悄省略。** 排行榜尾部标 `… N more`，火焰图
标 `N 帧过窄未显示`。**悄悄丢掉窄帧会让「我看全了」变成一个错觉**——这比
不画更危险。同理，窄帧也不做「最小宽度 1 格」的兜底，那会让窄帧集体虚胖、
把宽帧挤走，图就假了。

### 3.1 Metric Bar

```
CPU  ████████▍░  84.3%          ← bar 走域色阶；数值 84.3% 走中性
CPU  ████████▉░  91.0%          ← 超阈值：只有数值转 danger 色，bar 不变
```

- 填充 `█` + 八分块尾格，底槽 `░`，宽度 10 / 20 两档
- 数值右对齐，恒带单位

> **⚠ 与 VISUAL.md 的一处冲突，已按 VISUAL.md 解。** 本文档 v0.2 原写「阈值着色：
> <60% accent · 60–85% warn · >85% error」，即把语义色刷到 bar 上。但 VISUAL.md §1.6
> 定死**语义色只上字符与短文本、永不上色块**。VISUAL.md 是更新的那份（v0.5 对 v0.2）
> 且是 ★ 主文档，所以现在的规则是：
>
> | | 走什么色 | 为什么 |
> |---|---|---|
> | bar 本身 | 域色阶顺序取档 | 它是**数据** |
> | 数值文字 / 前缀符号 | 阈值语义色 | 它是**结论** |
>
> 这不是折中。**一个 90% 的 CPU 利用率本身不是错误**——只有当它被判定为问题时，
> 才该出现语义色。把两者刷成一个颜色，等于宣布「数值大 = 出事了」，
> 而这在性能调优场景里恰恰经常是反的（利用率高往往是好事）。

### 3.2 排行 Ranking

```
Top Bottleneck
attention_fwd  ██████████████  18.6s   1024 calls
matmul_4096    ████▊            6.3s    512 calls
layernorm      ██▊              3.7s   2048 calls
               … 4 more
```

- 量程取**最大值**而非总和——长尾场景下用总和做分母会让所有 bar 都短到看不出差别
- **不画底槽**：底槽会把每行拉成等长，削弱长短对比，而排行看的就是长短
- 默认 Top10，尾部 `… N more` 可展开；行可选中（反色），Enter 下钻

### 3.3 多列条形

```
baseline  ██████     ███        ████████     ← 三个系列共用一个量程
方案 A    █████████  ██         ██████████
方案 B    ████████   █▌         ████████████
          QPS        P99        CPU
```

系列身份用**色阶**（分类取色），数值用**长度**。参数调优的方案对比表就是这个形态。

### 3.4 Sparkline · 折线 · 面积

```
折线 T2    ⢀⡠⠔⠊⠉⠑⠢⢄⡀⠀⢀⡠⠔⠊⠉⠑⠢⢄     2×4 = 8 倍密度
面积 T2    ⣠⣴⣾⣿⣷⣶⣤⣀⣠⣴⣾⣿⣷⣶⣤⣀⣠⣴
Sparkline  ▂▃▅▇▆▃▂▁▂▃▅▇▆▃▂▁▂▃▅▇       ← T2 掉下来就是它
```

- 窗口右对齐：最新样本贴右边缘，切换渲染层时视线不用重新找位置
- 采样率档位 250ms / 500ms / 2s / 5s，跟 btop 一致
- **整条线一个亮度**，档位由当前值决定。逐点上色会让一条线出现五种亮度，读起来是噪声

### 3.5 双向面积

```
↑ up    ⣀⣠⣴⣶⣤⣀⣀⣠⣴⣿⣷⣦⣄⣀⣠⣴⣶⣤⣀   1.30 KiB/s
↓ down  ⠉⠛⠿⣿⣿⠿⠛⠉⠙⠻⢿⡿⠟⠋⠉⠛⠿⠟⠉   346 B/s
```

网络收发、PCIe/HBM 读写、Host↔Device 拷贝。上下对称让方向差异一眼可见——
前提是**两半共用量程**，否则「上下一样高」不代表「收发一样多」。

### 3.6 散点

Roofline（compute vs memory bound）、batch-latency 曲线、量化前后的精度-性能。

点阵画布天然适合散点：**一个字符格能放 8 个独立的点**，密集区自然加深、稀疏区
仍看得见单点。块字符做不到——一格一个方块，两点落在同一格就只剩一个。

### 3.7 火焰图

```
main              ██████████████████████████████
ngx_http_process  ██████████████████░░░░░░░░░░░░
crypto_aes        █████████░░░░░░░░░░░░░░░░░░░░░
                  1 帧过窄未显示
```

- 按深度分行，深度方向**不做降采样**——火焰图的价值在于栈的形状，压扁了就没了
- 窄于 1 格的帧直接丢弃并计数上报（见 §3.0 规则③）
- 每层用不同色阶区分深度，同层内用档位表达耗时

### 3.8 泳道 Timeline

```
        0ms                      100ms
CPU     ████████        ████
NPU           ████████████████
HBM       ██████████████████████
```

泳道顺序按**首次出现**排，不按字母序——Trace 的阅读顺序是执行顺序，
按字母排会把 CPU / NPU / HBM 打散，而「谁在等谁」正是要靠相邻行看出来的。

### 3.9 水位

```
░░░       ← 水位是「还剩多少」
▄▄▄
███       38.2 / 64 GiB
███
```

和横向 bar 的区别不只是方向。**水位表达「还剩多少」，bar 表达「占了多少」**——
内存、显存、上下文水位这类「有容量上限、快满了要出事」的量用竖槽更直观，
因为人对液面高度的直觉比对条长度更强。

### 3.10 进度

```
已知  ████████████████████▍░░░░░░░░  68%
未知  ░░░░░░██░░░░░░░░░░░░░░░░░░░░  ⠹ 采集中
```

**给不出进度就不画进度条。** 未知时画一个跑动的窄块，诚实表达「在动，但不知道
还有多久」。画一条匀速涨的假条是在骗用户——这条在 VISUAL.md §5 里是明令禁止项。

Braille spinner 只在**真实 pending** 的工具调用上转；RTT > 80ms 时降到 4fps。

### 3.11 分段

```
Memory  ██████████████████████░░░░░░░░  38.2 / 64 GiB
        used 22G   cached 12G  kv 4G  free 26G
```

一条 bar 表达多个量。末段吸收取整误差，保证总宽精确——差一格在终端里看得见。

### 3.12 像素数字

```
███ ██   ███         ← 5 行 × 3 列，仅用 █
█ █  █     █
███  █   ███   k QPS
█ █  █   █
███ ███  ███
```

- **仅用于数字与 `. % + - × / :`，正文永不像素化**（VISUAL.md §7）
- 遇到字母直接报错，不静默替换——静默降级会把 `12.3GB` 渲染成 `12.3`，
  **丢了单位的数字比没有数字更糟**
- 试过 3×3，太小：只用 █ 的话 2 / 3 / 8 几乎一样，得靠半块凑，而混半块的数字
  在不同等宽字体下基线会飘

### 3.13 数图 Stat Tile

```
QPS    61.2k   +45%  ▂▃▄▅▆▇█        ← 值 + 变化 + 走势
P99    12ms    −33%  ▇▆▅▄▃▂▁
内存   38.2GiB       ████████░░     ← 有容量上限时画占用条
```

光有数字不够——「QPS 61k」本身无法判断好坏。一块 tile 至少要回答三个问题：
**现在多少 · 和之前比如何 · 最近怎么走的**。

- `higher_is_better` 决定 delta 的正负被读成改善还是退化（P99 降了是好事）
- **没有基线就不下结论**，delta 留空而不是显示 0%
- delta 是 tile 上**唯一**该出现语义色的地方——它是结论；数值与 bar 一律中性或域色阶

### 3.14 热力网格

```
64-core heatmap
  0-15  ████████████████   NUMA0 ██████░░  80%
 16-31  ████████████████   NUMA1 ██░░░░░░  22%
 32-47  ████████████████   NUMA2 ██████░░  74%
        ⚠⚠⚠⚠⚠                              ← AI 标注层，独占一行
 48-63  ████████████████   NUMA3 ███░░░░░  31%
⚠ AI: core 34-38 持续 >80%，疑似跨 NUMA 内存访问
```

- 颜色承载数值，**位置承载拓扑**
- **AI 标注层独占一行**，不插在单元格之间。角标插在格后面会把整行往右挤、
  NUMA 条跟着错位——网格靠位置表达拓扑，一错位这张图就废了
- T1 降级时颜色被抽掉，**强度必须由字形 `░▒▓█` 接住**，否则退化成一片同样的
  方块，那是丢信息不是降级

### 3.15 Tree · Graph · Diff · Score Ring

```
Tree     Model              Graph    app                Diff   - _mm_pause();
          ├ Layer1                    │                        + asm("yield");
          │  └ Attention  ⚠          runtime ── libcrypto
          └ Layer2                    │
                                     driver
```

- Tree：`├ │ └` 制图符 + 状态符号后缀；`h/l` 折叠展开
- Graph：纵向为主流向，横向为关联；根因/焦点节点反色 + 双线标记
- Diff：`-` danger 色 / `+` success 色；hunk 头 dim；行号列可开关
- Score Ring：圆环在 TUI 中降级为 `bar + 分级计数`——
  `Compatibility ████████░░ 82%   Critical 2 · Warn 8 · Fixed 21`

### 3.16 对齐：禁用裸 `ljust` / `rjust`

所有图元的标签与表格列必须走 [`render/text.py`](../app/devkitai/render/) 的
`fit()` / `pad()` / `truncate()`，**不许用 `f"{s:<12}"` 或 `len()`**。

Python 数的是码位，终端排的是单元格，一个汉字占 2 格：

```
f"{'折线':<12}"       补 10 个空格，实际占 14 格   ← 歪了
f"{'Sparkline':<12}"  补 3 个空格，实际占 12 格    ← 对的
```

同一张表里两种标签混用，列就是歪的。**这类 bug 只在中文标签下出现，
纯英文界面上怎么测都测不出来**——所以靠纪律，不靠自觉。

## 4. 组件状态规范

所有交互组件必须定义 5 态：`default / focused（反色或 accent 边框） / selected / disabled（dim） / error`。
所有异步组件必须定义 3 态：`loading（spinner） / loaded / failed（✕ + 重试）`。
