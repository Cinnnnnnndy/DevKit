## 0. 定位与方法

第一部分是**空间学**：Cell 分辨率、画布分层、布局范式、产品谱系。
第二部分是**操作学**：同一块 Cell 网格，人怎么把意图打进去，Agent 怎么把过程吐回来，两边怎么谈判。

两部分不重复触点。第一部分已判定的结论（键位体系、输出折叠、diff 粒度、窄屏降级、原生能力保全）在此只作前提引用。

### 为什么必须重取证据

AI Agent TUI 这一层三个月翻一次。可核对的例子：Claude Code 在 2026-07-14 → 08-20 的 37 天里发布了 20 多个带 TUI 行为变更的版本（2.1.208 → 2.1.237）。

**任何超过半年的 AI TUI 交互结论都要重新验证。**

### 证据规则

1. **版本号 + 日期是硬要求**。拿不到版本号写「文档态」，拿不到日期标 ⚠️ 待核查。
2. **一手 > 二手**。官方 changelog / 官方文档 / 仓库 README 为一手；技术媒体与聚合站为二手，仅用于「存在性」不用于「细节」。
3. **行为差异优先于功能罗列**。「有没有 @ 引用」没有信息量，「@ 补全在多行输入里高亮偏移一格、8/18 才修」才有。
4. **Bug 与说明书同等重要**。一条被修掉的渲染 bug，等于一条被公开的实现约束。

### 口径澄清：「harness」

2026 年该词有两个所指：① 泛指 Agent 脚手架层（组装上下文 → 调模型 → 解析回复 → 派发工具）；② 特指以此自我标榜的一类产品，代表是 **Grok Build**（SpaceXAI，2026-07 开源）与 **Pi**。本报告两者都收。

## 2. 输入方式：一个输入框有七层

| 层 | 名称 | 内容 |
|---|---|---|
| L7 | 语义层 | 意图 · 计划 · 引用哪些文件 · 用哪个 agent |
| L6 | 补全与提示层 | `/` 命令 · `@` 文件 · `@` 会话 · `:emoji:` · 模糊匹配与错字处理 |
| L5 | 模式层 | `!` 转 shell · `#` 记忆 · Vim NORMAL/INSERT · 队列态 · 草稿态 |
| L4 | 编辑层 | 多行 · 光标自由 · Readline/Emacs 键 · 历史 · 外部编辑器 · 拼写检查 |
| **L3** | **粘贴通道** | bracketed paste · CRLF · 多行折叠 · 图片粘贴 · 启动期缓冲输入 — **第一大 bug 源** |
| **L2** | **键盘协议层** | Kitty keyboard protocol · extended key reporting · `Ctrl+J` 与换行的冲突 — **第二大 bug 源** |
| L1 | 字符与宽度层 | CJK 双宽 · emoji · Nerd Font 字形 · 截断与 ANSI 保留 |

**为什么这么排**：本窗口 Claude Code 的输入相关修复里，落在 L1–L3 的数量超过 L4–L7 的总和。「输入框做得好」在 TUI 里的实际含义是**协议层与宽度层没有漏**。

### L2 键盘协议层 · 三条硬事实

- **协议要主动协商**：pi-tui 启动时协商 Kitty 键盘协议，目的是分清 `Esc` 与 `Alt+x` 序列，并拿到 key-release 事件。
- **Ctrl+J 是雷**：开了 extended key reporting 的终端上，`Ctrl+J` 在 agent view 输入里插不进换行——Claude Code v2.1.212（7/17）修一次，v2.1.229（8/12）又修一次，第二次顺手把换行快捷键**补进 `?` 帮助面板**。
- **复制键归协议管**：全屏下 `Ctrl+Shift+C` 复制；**仅在支持 Kitty 键盘协议的终端**（kitty / WezTerm / Ghostty / iTerm2）上 `Cmd+C` 才可用 → **提示文案必须按能力动态变**。

### L3 粘贴通道 · 四个真实故障

| 故障 | 产品 · 版本 | 抽象规则 |
|---|---|---|
| 多行粘贴被压成一行，换行变成字面量 `j` | Claude Code v2.1.221 · 8/4 | 粘贴解码必须**与按键解码分离** |
| CRLF 粘贴、行尾空白、超长 URL 折行 | Codex 0.148.0 · 8/18 | Windows 剪贴板是**默认场景不是边缘场景** |
| 提案内容里的 CRLF 归一为 LF | Gemini CLI v0.55.1 · 8/11 | 行尾归一做在**入口**，不是 diff 阶段 |
| 启动期缓冲输入误激活提示 | Codex 0.148.0 · 8/18 | 启动窗口期必须**吞掉或隔离**缓冲输入 |

> **把等待变成输入**：Codex 0.148.0 的「TUI 还在初始化时就能先打字」+「resume/fork 进度在启动过程中就显示」，是本窗口最值得抄的小设计。DevKit 启动要连 SSH、探终端能力、拉工程索引，这段时间只会更长。

### L4–L6 逐项对比

| 触点 | 最优解 | 判断 |
|---|---|---|
| 换行绑定 | opencode 给 **4 个**：`shift+↵` `ctrl+↵` `alt+↵` `ctrl+j` | 冗余是对的——不同终端能送出的组合键不一样 |
| 行内编辑 | Vim（Claude Code，`vimInsertModeRemaps` 可把 `jj` 映射成 Esc）/ Readline（opencode）/ 可配置（Codex 7 个 keymap context） | **三流派并存未收敛，可配置是唯一解** |
| `/` 命令菜单 | Claude Code 8/10–8/12：蓝色**只标选中行**，匹配字符**加粗**而非变色，emoji/带音标命令名保留字形 | **用字重而非颜色表示匹配**是纯 TUI 的正确解——色要留给语义 |
| 打错命令 | Claude Code v2.1.229 → 2.1.237：Enter 打错**不再模糊匹配去跑最近的那个**，直接报错；前缀与别名仍可跑 | **行业级教训**：Agent 场景下「猜你想跑哪个」= 可能替你跑了不该跑的 |
| `@` 文件引用 | opencode：`@` 模糊搜、内容自动进对话、`@alias` 预置引用；Crush：附件 chip 可点 ✕ | 已是共识，差距在**渲染精度**（CC 多行输入里高亮曾整体偏移 ≥1 字符，v2.1.235 · 8/18 才修）与**移除路径** |
| `@` 引用「人」 | Claude Code v2.1.232 · 8/13：`@` 可点名**另一个会话**并直接发消息 | **@ 的宾语从「文件」扩展到「会话」** |
| 队列与草稿 | Claude Code v2.1.234 · 8/17 连修三个队列态 bug | **队列是新增的一等状态**，且与 Esc / 历史 / 模式前缀全都会打架 |
| 拼写检查 | Claude Code v2.1.235 · 8/18：`spellcheck` 设置挂 `aspell`/`hunspell`/`ispell` | 独一份。思路是**不自己实现，挂系统已有的** |

### 给 DevKit 的输入结论

1. 换行给足 4 个冗余绑定，并在 `?` 帮助里列出——SSH + tmux 会吃掉其中任意一个。
2. 粘贴独立解码：bracketed paste 单独通道，CRLF 入口归一，多行永不折叠。
3. **命令打错必须报错，不许猜**——Agent 场景下模糊执行是安全问题。
4. 匹配高亮用字重不用颜色，颜色预算留给语义。
5. 队列做成显式一等状态，队列 × Esc × 历史 × 模式前缀的四向组合在规范里穷举。
6. 冷启动期就接受输入，并显示恢复进度。

## 3. 配置方法：四种哲学，且互不兼容

| # | 哲学 | 代表 | 做法 | 可抄的点 |
|---|---|---|---|---|
| ① | **声明式命名空间** | Codex | `~/.codex/config.toml` 的 `[tui]` 段（自 v0.128.0 成体系） | keymap 按 **7 个 context** 分层（global/chat/composer/editor/pager/list/approval），具体覆盖全局；**解绑用空数组** `open_external_editor = []`；**`status_line` 与 `terminal_title` 都是有序数组**——用户决定显示什么、按什么顺序 |
| ② | **Schema 化分家** | opencode | `tui.json`（主题/键位/滚动/光标/鼠标/通知，带 `$schema`）与 `opencode.json`（服务端与运行时）**两个文件** | **换终端只改 `tui.json`，换模型/服务端只改 `opencode.json`**；键位可设 `"none"`/`false` 禁用 |
| ③ | **对话内改配置** | Claude Code | `settings.json` + 环境变量 + 会话内 `/config` 对话框三条腿 | v2.1.234 · 8/17：`/add-dir` `/autocompact` `/theme` `/help` `/config` `/advisor` **可在 Agent 工作到一半时打开**；`/permissions` 改完**立刻对本轮剩余部分生效** |
| ④ | **可解释性优先** | Grok Build | `~/.grok/config.toml` + **`grok inspect`**（列出配置来源、instructions、skills、plugins、hooks、MCP servers） | 配置有五层来源时，用户真正的问题是**「我这条到底从哪儿来的」** |

### 配置分层（越靠下越优先）

```
1 内置默认      用户看不见，但必须能被 inspect 出来
2 用户级        ~/.codex/config.toml · ~/.claude/settings.json · ~/.grok/config.toml
3 项目级        .codex/config.toml · AGENTS.md / CLAUDE.md   ← 信任边界也在这一层
4 Profile 预设  Codex --profile 可整套切换视觉配置
5 命令行 flag   最高优先级，且不一定能被带过重启
6 会话内临时改  /config · /model · /permissions   ← 行业空白：写不写回文件、下次还在不在，各家不一致
```

### 本窗口最贵的一条配置教训：重启会丢配置

Claude Code v2.1.234 · 8/17 修了两个同源问题：接受「要不要试试全屏渲染器」后重启，**丢掉了 `--dangerously-skip-permissions` 等权限模式、工具允许/拒绝规则、模型与 effort 参数**；`/tui` 也会丢掉启动时传的 `--allowed-tools`/`--disallowed-tools`。

修复方式很坚决：**凡是带不过去的限制，就拒绝切换并说明原因**（错误名 `Cannot switch renderers in this session`）。

> **对我们的含义**：任何「切换视图 / 渲染器 / 主题」的动作，如果实现是 relaunch，就必须先做**可携带性检查**，宁可拒绝也不能静默降权。

### 主题系统

- **Codex**：syntect 引擎（与 `bat` 同源）· 32 套内置 · 支持把 `.tmTheme` 丢进 `$CODEX_HOME/themes/` · `/theme` 带**实时预览**。→ **复用编辑器生态的主题格式，不要自创。**
- **Yazi v26.8.15**：**自动明暗切换**（检测算法本窗口刚调过）+ 主题热重载 DDS 事件供插件监听。→ **主题不该只在启动时定一次。**

### 给 DevKit 的配置结论

采 opencode 的**分家** + Codex 的**结构** + Claude Code 的**入口** + Grok Build 的 **`inspect`**；主题**复用 `.tmTheme`**。

| **作用域扩张** | Claude Code `/add-dir` v2.1.234 · 8/17 起**可在工作中执行**，并新增 `DirectoryAdded` hook | **作用域变更是可被 hook 的事件，不是静默的内部状态修改** |

## 5. 对话压缩：四种策略，一个共同的 UI 债

| 策略 | 代表 | 做法 | 取舍 |
|---|---|---|---|
| **全量替换 + 结构化交接** | Grok Build | 压缩产出**九段式 successor brief**（意图/涉及文件/报错/未完成事项/下一步等固定分节）；压缩提示词明写：**若更早轮次已含上一次压缩摘要，视其为权威** | 结构化 = 可校验、可迭代压缩不失真；代价是模板僵硬。⚠️ 二手来源待核查 |
| **自动压缩 + 全量 scrollback** | Claude Code | 全屏模式下**把每一次压缩之前的完整历史都留在应用内 scrollback**（v2.1.216 · 7/20），可反复压缩后仍滚回会话最开头。模型从摘要继续，**人从原文继续** | **本窗口最值得抄的一条**：把「模型的上下文」与「人的可见历史」正式分开 |
| **远端压缩** | Codex 0.147.0 · 8/7 | 为 Amazon Bedrock 启用**远程会话压缩** | 压缩成为可被后端接管的能力——有延迟、有失败态，必须有 UI |
| **压缩即重载** | Gemini CLI v0.54 · 8/6 | 修 `/compress` 引起的会话重载与 quota-fallback 工具响应丢失 | **反面证据**：压缩若实现为「重建会话」，会丢在途的工具响应 |

### 压缩的 UI 契约 · 5 条

1. **压缩失败必须是错误，不是静默**（CC v2.1.229 · 8/12：失败的 `/compact` 显示为错误，并解释为什么自动压缩没能救回来）。
2. **压缩后的读数必须立刻刷新**（CC v2.1.218 · 7/22：从消息选择器触发压缩后 `/context` 仍报压缩前的陈旧用量）——**用量读数陈旧 = 用户据此做的所有决定都是错的**。
3. **人的历史不随模型的上下文一起被砍**。
4. **迭代压缩不能失真**（Grok Build「把上一次压缩摘要当权威」）。
5. **压缩会重置周边状态，要显式声明**（权限缓存、LSP 上下文、成本计数）。

> **与第一部分衔接**：第一部分把 rewind 双向摘要列为「必抄」。本窗口补上边界：v2.1.216 · 7/20 起 `/rewind` **不再通过符号链接或硬链接恢复/删除文件**，并报告被跳过的路径。

## 6. 代码联动：LSP 从「上下文来源」变成「可调用工具」

1. **LSP 工具化**（Crush v0.86 · 7/20）：`lsp_rename`、`lsp_replace_symbol` 两个工具 + **fancy diff view 渲染重构预览**。重构不再是「让模型自己写正则改一堆文件」，而是**调语言服务器做语义级改名，再把结果作为 diff 给人看**。对 DevKit 的迁移场景（改 intrinsic、换头文件、替换编译选项）最直接可移植。
2. **diff 的数据源要绕开工程配置**（CC v2.1.222 · 8/4）：`/diff` 与文件编辑 diff 改用 **raw git blob 内容，忽略 workspace 配置的 diff driver**。→ **审查界面必须绕开一切「美化中间层」。**
3. **窄屏会吃掉 diff 的语义**（CC v2.1.216 · 7/20 修「窄布局下 diff 预览丢失行号与 +/− 标记」）。→ **diff 降级顺序写死：先丢上下文行 → 再丢语法高亮 → 行号与 ± 号永不丢。** opencode 的 `diff_style: auto | stacked` 是可配置版本。
4. **点击路径打开文件是一项权限决定**：Claude Code 全屏下 `Cmd`/`Ctrl`+点击可打开 URL 与工具输出里的文件路径；**但 UNC 网络路径（`\\server\share\file.ts`）被渲染成纯文本、不做链接**——因为打开网络路径可能把 Windows 凭据发给该主机。DevKit 会大量出现远程主机路径，必须照抄。
5. **ACP 正在成为编辑器联动的总线**：2025-06 协议创建 → 2025-12 JetBrains 内置 → 2026-01-28 与 JetBrains 合推公共 agent registry → 2026-01 Copilot CLI 支持 → 2026-03 25+ agent 采用 → 2026-04-29 成为 Zed 1.0 头号特性（⚠️ 二手）。Grok Build 的做法摆明了结论：**权限确认不能是「TUI 里的一个模态 hack」，必须是协议上可见、任何客户端都能渲染的决策。**
6. **worktree 成为并行改代码的标配**：Grok Build 的 `xai-fast-worktree`（子 agent 在隔离 checkout 上并行，⚠️ 二手）；Claude Code v2.1.212 · 7/17 修「worktree 创建会跟随仓库中提交的 `.claude/worktrees` 符号链接」（**worktree 路径是攻击面**）；lazygit `w` 直接从选中项建 worktree。

## 7. 图标与字符资产

**难点一句话**：display width ≠ 字节数 ≠ 码点数，而布局引擎只认 cell。

| 档 | 资产 | 约束 |
|---|---|---|
| T1 | **Nerd Font 图标** | 3600+ 字形。**必须用 Mono 变体**——保证每个字形恰好占一个 cell；也可只装 SymbolsOnly 走系统 fallback（Linux 需手工装 `10-nerd-font-symbols.conf`） |
| T2 | **Emoji** | 几乎所有终端都有，但**宽度不可靠**：多数双宽、部分单宽、ZWJ 组合序列各终端算法不一致 |
| T3 | **ASCII / Box Drawing** | 永远可用的底线。lazygit v0.63.x 把提交图换成兼容性更好的 Unicode 符号 |

### 本窗口三条具体证据

- **图标要进对话框**（Yazi v26.8.15 · 8/15）：输入框有了上下文相关图标；trash/delete/overwrite 确认框带上了文件图标。→ **高风险确认框里放被操作对象的图标**，把「你正在删的到底是什么」变成一眼可辨。
- **宽度计算要贯穿到截断**（pi-tui）：`visibleWidth()` 忽略 ANSI 算显示宽度；`truncateToWidth()` 在截断时保留 ANSI 并补省略号。→ **宽度函数是基础设施，不是某个组件的私有工具。**
- **一格之差会传染**（CC v2.1.233 · 8/14）：内容尺寸的浮层在文本被截断时**多渲染一列**；长预览**在 emoji 中间截断产生乱码**。两条同源：**measure 与 render 用了不同的宽度口径。**

### 给 DevKit 的图标决策

DevKit 跑在鲲鹏 Linux 服务器上、常是 `ssh` 进去的裸终端，**不能假设有 Nerd Font**：

1. 图标定义为**三档 token**（nerdfont / emoji / ascii），与第一部分的渲染分档（braille / block / tty）同构、共用同一次 capability 探测。
2. 默认档位按探测结果自动选，允许在 `tui.json` 里锁死。
3. **任何图标都不得承载唯一语义**——去掉图标后信息必须完整（同时满足 `NO_COLOR` 与屏幕阅读器场景）。

## 8. 左树与空间结构：一个反直觉的事实

**2026 年 8 月，主流 AI Agent TUI 里没有一个把「常驻左侧文件树」作为默认布局。** 这不是没做完，是主动放弃——它们用**模糊搜索取代了空间浏览**。

- **opencode**：侧栏 `<leader>b` 才出来，且在**右侧**。
- **Crush**：右栏，v0.86 起可滚动可聚焦（`j/k/g/G`）。
- **Claude Code**：**没有树**。
- 对照组：Yazi 的 Miller 三列；superfile v1.6.0 的**可隐藏可重排侧栏分区**；lazygit 的左栏是**上下文列表**（分支/提交/stash/worktree）而非文件树。

### 三种「找到东西」的范式

| 范式 | 代表 | 成立条件 | 失效场景 |
|---|---|---|---|
| 空间浏览（树 / Miller） | Yazi · superfile · lf | 用户**知道大概在哪**，层级稳定 | 单仓十万文件；用户不知道文件叫什么 |
| 模糊搜索（@ / fzf / 命令面板） | 全部 AI TUI · television channels · k9s `:` | 用户**知道名字片段** | 「我不知道要找什么，我想看看这个模块里有啥」——**DevKit 迁移场景的常态** |
| 结果驱动（列表即入口） | lazygit 左栏 · k9s 栈式下钻 | 存在**天然的实体列表** | 无天然列表的自由探索 |

### 给 DevKit 的判断（与主流分歧的一条）

AI 派放弃左树是合理的，但**不完全适用于我们**。它们面对的是「我知道要改哪个文件」的日常编码；DevKit 面对的是「一个陌生的百万行 C 工程要迁到 ARM，我不知道风险在哪」——用户给不出文件名片段，模糊搜索这条路是断的。

正确形态是第三种：**结果驱动的树**——节点不是目录结构，而是**风险项 / 待改项 / 编译失败项**。三条要求：

1. 树**可折叠、非默认常驻**（默认把宽度给对话流，一个键唤出）。
2. 树的分区**可隐藏可重排**（照 superfile v1.6.0）。
3. 树的选中**驱动右侧主区**（照 lazygit），而不是只做一次跳转。

## 9. 对白：对话流的呈现 + 打断对话的对话框

### A · 对话流的呈现

| 触点 | 证据 | 规则 |
|---|---|---|
| **流式性能** | CC v2.1.232 · 8/13 改进全屏流式，长会话**不再在每次更新时把整个对话重新规范化**；v2.1.216 · 7/20 修「规范化成本呈二次增长」；opencode 把 markdown 解析移出主线程 | **渲染成本必须与「新增内容」成正比，不能与「历史长度」成正比** |
| **工具卡片** | CC v2.1.210 · 7/14 折叠的工具摘要行加**实时计时器**（长工具「看得见地走动」而非像卡死），且计时器**调暗**以免抢注意力；全屏下**点击折叠的工具结果即可展开**，调用与结果一起展开 | ① 进行中必须有**时间维度**的证据；② 新增信息不得抢占既有信息的视觉层级 |
| **思考过程** | VSCode 侧折叠显示 `Thought for Ns` 并**在本轮结束时自动重新折叠**；Gemini v0.55.1 · 8/11 在剥离 thought 部分时**保留 functionCall 的 thoughtSignature** | 「折叠」是显示层动作，**不能连带丢掉模型协议需要的字段** |
| **Markdown 渲染** | CC v2.1.235 · 8/18 修**三级以上嵌套列表错位**并给折行列表项加**悬挂缩进**；v2.1.208 · 7/14 超大表格 **>200 行只显示前 200 行 + 「… 还有 N 行」**；v2.1.229 · 8/12 极窄终端下渲染进度条或表格会 `RangeError` **崩溃** | ① 嵌套缩进与折行悬挂缩进一起定义；② **任何无界内容都要有截断上限 + 明确省略提示**；③ 极窄宽度是**崩溃级**输入，必须有下限保护 |
| **极简视图** | `/focus` 只显示最后一条 prompt、工具调用一行摘要（含 diffstat）、最终回复；设置**跨会话持久** | **视图密度是长期偏好，不是一次性开关** |
| **搜索与交还** | `Ctrl+O` 进 transcript 模式得到 `less` 风格导航：`/` `n`/`N` `{`/`}`（**在 prompt 之间跳**）`g`/`G` `Ctrl+U/D/B/F`；`[` 把整段对话**展开写回终端原生 scrollback**，`v` 写临时文件并用 `$VISUAL`/`$EDITOR` 打开 | **`{`/`}` 按 prompt 跳转是对话流特有的导航单位**——DevKit 应有等价的「按任务跳转」 |

### B · 对话框 · 九条教训（本窗口密度最高的一组）

1. **对话框文案必须与它实际授予的权限完全一致**（CC v2.1.229 · 8/12 与 v2.1.235 · 8/18 连续两版）。
2. **看不全就不许永久授权**——内容无法完整显示时，直接不给「不再询问」选项。
3. **不可见字符是攻击面**（v2.1.223 · 8/6 制表符/不可见 Unicode 把内容藏出批准对话框；v2.1.221 · 8/4 双向覆写、零宽、形近引号未中和）。
4. **导航与确认之间有竞态**（v2.1.235 · 8/18：方向键 + Enter 快速连按会选中上一个高亮项）——**后果是误批准**。
5. **子控件键位不能溢出成主操作**（v2.1.235：权限对话框的备注输入框里按 `Shift+Tab` 会直接批准这次编辑）。
6. **对话框不得越界、不得裁掉键位提示**（v2.1.232 · 8/13 伸出右边缘 / `/config` 裁掉底部提示 / transcript 提示在 <104 列折行；v2.1.234 `/model` 比终端还高）。
7. **信任对话框要点名它覆盖的根目录**（v2.1.216 · 7/20）；**嵌套 git 仓库不再从父目录继承信任**（v2.1.232 · 8/13）。
8. **对话框要能在 Agent 工作中打开**（v2.1.234 · 8/17；`/permissions` 改完立刻对本轮剩余部分生效）。
9. **启动期的第一次按键不能被当成批准**（v2.1.237 · 8/20 托管设置批准提示不显示却吃掉首次按键）。

> **压成一句**：在 TUI 里，对话框是唯一一个「用户按一个键就产生不可逆后果」的组件，它的验收条件应该比任何其他组件都严。

## 11. 需求没点名、但同样是 TUI 一等场景的 8 件事

### ① 中断与排队

Esc 的行为是 `(当前焦点, 是否有选区, 是否有队列, 是否在跑)` 的函数。本窗口证据：CC v2.1.234 修「选中排队消息时按 Esc 会误中断本轮」；v2.1.236 改为**全屏下 Esc 不再清除鼠标选区但仍中断/关闭对话框**；v2.1.216 修「长会话且有后台任务时空闲提示符下连按两次 Esc 打不开 rewind 选择器」；v2.1.218 修「按左箭头会在无撤销的情况下丢弃整个对话」（改为先弹确认）。

> **任何「一个键即不可逆丢失」的路径都要加确认。**

### ② 鼠标捕获 vs 终端原生选择

| 档位 | 开关 | 保留 | 失去 |
|---|---|---|---|
| 全捕获（默认） | — | 点击定位光标 · 点击展开工具结果 · 点击选项 · 拖选（松手自动复制）· 双击选词（按 iTerm2 词边界，路径算一个整体）· 三击选行 · `Shift+方向键` 键盘扩展选区 · 滚轮 | 终端原生 copy-on-select |
| 只保留滚轮 | `CLAUDE_CODE_DISABLE_MOUSE_CLICKS=1` | 滚轮/触控板滚动 | 左键点击类交互 |
| 完全放弃鼠标 | `CLAUDE_CODE_DISABLE_MOUSE=1` | 无闪烁渲染 + 内存恒定 + 键盘滚动 | 点击定位/展开/链接/滚轮 |

**「一次性原生选择」的按键因终端而异**：Terminal.app `Fn` · iTerm2 `Option` · VS Code 系 `Shift` · 其余多数 `Shift`；**产品在屏幕提示里显示正确的那个键，SSH/tmux 下探测不到时把候选键都列出来**。剪贴板通路分场景：本地 `pbcopy`/`wl-copy`/`xclip`/`Set-Clipboard`，tmux 里额外写 tmux buffer，SSH 下退回 **OSC 52**，**每次复制后弹提示告诉你走的是哪条路**。

> **DevKit 主场景就是 ssh + 可能套 tmux。「复制走了哪条路」的提示与「探测不到就列候选键」必须抄。** OSC 52 还有一层坑：部分终端默认禁用。

### ③ 滚动与自动跟随

- 向上滚动即**暂停自动跟随**；浮动 `Jump to bottom` 按钮出现并显示 `3 new messages` 计数。
- **按钮的键盘提示随「你的键盘能送出什么」而变**（MacBook 发不出 `Ctrl+Fn+→`，提示改成点击或 `Fn+↓`）；**终端太窄时按钮缩短文案，而不是折行压到下面那行内容上**。
- 滚动速度是一等设置：`CLAUDE_CODE_SCROLL_SPEED`（0.25–20）、`/scroll-speed` 打开**带尺子、可边滚边感受**的对话框、`wheelScrollAccelerationEnabled` 关加速。
- **宿主差异单独处理**：JetBrains 终端事件速率高得多，忽略全局倍率并自适应；2025.2 已知滚轮 bug 由产品运行时探测绕开。

> 一旦进了 alt-screen，**滚动的手感、速度、加速曲线、跟随策略全部变成产品责任**。

### ④ 注意力与通知

- **opencode**：`attention` 配置，**提问 / 权限请求 / 会话事件**三类触发桌面通知与提示音，**音量可调、支持自定义音效包**。
- **Codex**：`tui.notifications`（布尔或数组）；`tui.terminal_title` 可放 `spinner`。
- **Claude Code**：后台 agent 等待输入时 agent view 页脚提示**在计数变化时用颜色强调**；`/goal` 空闲会话按 **30min → 1h → 2h 退避自动汇报**。
- **反面细节**：CC v2.1.236 · 8/19 修「tmux + iTerm 集成下终端标签标题不停跳动」——原因是**每 960ms 写一次标题做动画**，改为**只在文本真正变化时才写**。→ **终端标题是别人的 UI，不是动画区。**

### ⑤ 无障碍

Claude Code v2.1.208 · 7/14 引入屏幕阅读器模式（`--ax-screen-reader` / `CLAUDE_AX_SCREEN_READER=1` / `"axScreenReader": true`），随后持续打磨：修「每次退格都重读整行」→ 行尾删除只回显被删字符；v2.1.217 · 7/21 为按词/按行删除播报被删文本；v2.1.229 · 8/12 `/effort` 选择器**改渲染成带编号的列表 + 输入数字**。

**最关键的架构决定**：屏幕阅读器模式下**强制使用经典渲染器**，只有 attach 上去的后台会话例外；此时执行 `/tui fullscreen` 会**打印解释而不切换，也不改动已保存设置**。

> 无障碍在 TUI 里是**一条平行的渲染路径 + 一套平行的控件形态**，不是样式开关。

### ⑥ 终端能力协商与降级

| 能力 | 协商 | 失败怎么办 |
|---|---|---|
| 同步输出 `CSI ?2026` | 启动时探测；pi-tui **把每次更新都包在 `\x1b[?2026h ... l` 里** | **tmux 3.6 及以前不实现同步输出** → 更多闪烁；建议升级或不在 tmux 里跑 |
| Kitty 键盘协议 | pi-tui 启动时协商 | 回退普通键序解析，部分组合键不可用 → **提示文案要跟着变** |
| 图形协议 | Kitty graphics / iTerm2 inline images | 降级为**文字占位**；**alt-screen 下 iTerm2 协议一律占位**——该协议缺少删除与裁剪 |
| 增量重绘 | 只发变化的 cell | **ConPTY 系会把定位写入合并错，留下上一帧残影** → `CLAUDE_CODE_ALT_SCREEN_FULL_REPAINT=1` 全量重绘 |
| 鼠标上报 | 终端需转发鼠标事件 | iTerm2 是 per-profile 开关；tmux 需 `set -g mouse on`，**检测到未开会在启动时给一次性提示** |
| 整体兜底 | — | CC v2.1.237 · 8/20：**全屏渲染器启动失败一次后回落到经典渲染器**，而非永久失败 |

**已知不兼容也要写进规范**：全屏渲染与 **iTerm2 的 tmux 集成模式（`tmux -CC`）不兼容**——滚轮无效，双击可能损坏终端状态。

### ⑦ 计费与用量

Codex 0.148.0 · 8/18 把**预估 thread credits / 成本**同时放进 `/status`、状态行和**终端标题**。Claude Code：v2.1.211 · 7/15 修 `/clear` 不重置会话成本计数；8/7–8/8 加入网关消费上限支持，**触顶提示写明上限值、重置时间和运营方留言**；v2.1.234 · 8/17 `/config` 新增「用量触顶后自动继续」开关。

> 成本是**会话级状态**，不是消息级装饰。**清空会话必须重置计数**；**触顶提示必须给出上限值与恢复时间**。

### ⑧ 多端与远程

Grok Build 的 **leader 模式**；Claude Code 的 **Remote Control / cloud session**（`ListAgents` 把断开的标 `offline`、云会话标 `cloud`；`/teleport` 提示怎么在本地接着干）；Amp 重构 CLI 的目标之一是**可远程控制**。

> **对 DevKit 是刚需**：会话跑在鲲鹏服务器上，一次迁移编译几十分钟。「关掉本地终端 → 会话继续 → 明天换台机器接回来」是基本诉求。**这是架构决定，第一版不做以后补不上。**

## 12. 模式识别 · 2026 夏收敛出的 12 条（编号接第一部分 M1–M7）

| # | 模式 | 证据 | 代价 / 反证 |
|---|---|---|---|
| M8 | **全屏 alt-screen 成为默认，并自带一整套逃生舱** | Claude Code 对新用户默认全屏；Grok Build README 第一句；Crush / opencode 均常驻全屏 | 要自建滚动、选择、搜索、复制四套能力，且每套都要给关闭开关 |
| M9 | **渲染更新必须原子化（同步输出）** | pi-tui 全部更新包在 `CSI ?2026`；Claude Code 启动探测并使用 | tmux ≤3.6 不实现 → 闪烁回来，产品修不了 |
| M10 | **渲染成本与「变化量」成正比，而非与「历史长度」成正比** | Claude Code 全屏只渲染可见消息、内存恒定，连修两次规范化成本增长；opencode markdown 解析移出主线程；pi-tui 差分渲染 + 组件级缓存 | 差分渲染在 ConPTY 上留残影 → 必须提供全量重绘开关 |
| M11 | **配置从「文件」走向「文件 + 会话内对话框 + 环境变量」三条腿** | Claude Code 三者并行且对话框可在工作中打开；Codex 分层 + profile；opencode UI/Runtime 分家 | 三条腿必然产生优先级歧义（`ANTHROPIC_DEFAULT_MODEL` vs `ANTHROPIC_MODEL` 要专门解释） |
| M12 | **模型的上下文与人的可见历史正式分离** | Claude Code 压缩后仍保留全部历史在应用内 scrollback；Codex sections + 增量浏览 | 需要独立存储，内存/磁盘成本上升 |
| M13 | **压缩产出结构化摘要，而非自由文本** | Grok Build 九段式 successor brief ⚠️；Codex 支持远端压缩 | 模板僵硬；跨语言/跨领域分节可能不适配 |
| M14 | **LSP 从上下文来源升级为可调用工具，并配专门的预览 UI** | Crush `lsp_rename`/`lsp_replace_symbol` + fancy diff；Claude Code 修「LSP 断连导致整包 prompt cache 失效」 | LSP 连接抖动波及缓存与成本 |
| M15 | **Agent 协议化：TUI 只是众多客户端之一** | ACP 成为 Zed 1.0 头号特性、JetBrains 内置、25+ agent 采用；Grok Build 把 ACP 当内部产品 API ⚠️ | 权限/批准/diff 必须先有协议级数据结构，前期成本更高 |
| M16 | **会话具备「工作项」属性：可分叉、可归档、可分区、可后台** | Codex sections + archive + `exec fork`；Claude Code `/fork` 到后台 + agent view + Needs input | 会话身份必须用稳定 ID，路径派生会串台 |
| M17 | **权限对话框文案与授权范围逐字对应，看不全就不给永久授权** | Claude Code 在 8/4、8/12、8/18 三次迭代同一条规则 | 「不再询问」在复杂命令上频繁不可用——这是正确的代价 |
| M18 | **终端能力探测一次、全组件复用，并对已知不兼容宿主直接点名** | 同步输出 / Kitty 键盘协议 / 图形协议 / 鼠标上报四类探测；`tmux -CC` 被官方文档写明不兼容 | 探测矩阵持续膨胀，需要版本化管理 |
| M19 | **无障碍是一条平行渲染路径，不是样式开关** | Claude Code 屏幕阅读器模式强制经典渲染器、选择器改编号列表、删除播报 | 两条渲染路径 = 两倍验收成本 |

## 13. 反面教训 · 9 个新坑（接第一部分 F1–F7）

| # | 坑 | 证据 | 规范里怎么防 |
|---|---|---|---|
| F8 | **切换渲染器/视图时静默丢掉启动限制** | CC v2.1.234 · 8/17：丢权限模式、工具允许/拒绝规则、模型与 effort；`/tui` 丢 `--allowed-tools` | relaunch 类操作先做**可携带性检查**，带不过去就**拒绝并说明原因** |

| F11 | **对话框超出终端边界，或裁掉自己的键位提示** | CC v2.1.232 · 8/13、v2.1.234 | 浮层尺寸**先按终端夹取再渲染**；**键位提示行不可裁**，内容区先滚动 |

| F13 | **启动窗口期把缓冲输入当成用户确认** | CC v2.1.237 · 8/20；Codex 0.148.0 | 启动期**丢弃或隔离**预输入；确认类 UI 未完成绘制前不接受按键 |
| F14 | **会话身份由路径派生 → 长路径下串项目** | CC v2.1.224 · 8/7 | 会话主键用**稳定 ID**；路径只作展示；对长路径与同前缀路径专门写测试 |

## 14. 机会点 · 8 条（差异化价值 × 实现成本排序）

| # | 机会点 | 价值 | 成本 | 要点 |
|---|---|---|---|---|
| 01 | **上下文用量归因面板** | ★★★★★ | ★★☆☆☆ | 全行业只显示「用了多少」，**没人回答「谁在占」**。拆成系统提示 / 工程索引 / 已引用文件 / 工具结果 / 压缩摘要五段，可下钻、可释放。DevKit 的工程索引与编译日志占比极高 |
| 02 | **结果驱动的左树（风险树，不是文件树）** | ★★★★☆ | ★★★☆☆ | 节点是风险项/待改项/编译失败项；选中驱动右侧（lazygit）；分区可隐藏可重排（superfile）；默认折叠一键唤出。**与所有 AI Agent TUI 最正当的一处形态差异，理由来自场景** |
| 03 | **缺配置 = 一等公民的暂停-补齐-续跑** | ★★★★☆ | ★★☆☆☆ | 第一部分判定的空白仍在。零件已有：`/permissions` 工作中可改且立刻生效 + `/goal` 退避式汇报。**从断点续跑而不是重来** |
| 04 | **配置来源可追溯：`devkit inspect`** | ★★★☆☆ | ★☆☆☆☆ | 来自 `grok inspect`。DevKit 装在客户服务器上、现场排查成本极高、配置有五层来源。**成本很低、诊断价值极高，第一版就该有** |
| 05 | **会话与 TUI 进程解耦（leader 模式）** | ★★★★☆ | ★★★★☆ | 一次迁移编译几十分钟，用户会关掉本地终端。**架构决定，第一版不做以后补不上** |
| 06 | **三档字符资产 token（nerdfont / emoji / ascii）** | ★★★☆☆ | ★★☆☆☆ | 与渲染分档同构、共用同一次 capability 探测；图标不得承载唯一语义；measure 与 render 共用同一个 display-width 函数 |
| 07 | **审查界面绕开一切美化中间层** | ★★★★☆ | ★☆☆☆☆ | diff 用 raw git blob；降级顺序定死：先丢上下文行 → 再丢语法高亮 → **行号与 ± 号永不丢** |
| 08 | **把权限 / 计划 / diff 定义成协议数据结构** | ★★★☆☆ | ★★★☆☆ | 即使第一版只有 TUI，这三类交互的数据结构也独立于渲染层定义。以后接 IDE / Web 评审页 / CI 报告时**渲染换掉、语义不动** |
