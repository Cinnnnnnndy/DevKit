# Kunpeng DevKit AI 全局 UI 规范

> 本文件是供后续实现使用的全局 UI 契约。当前状态为 `draft`：在现有设计结论完成汇总并通过人工审核前，不属于已生效的正式规范。

## 使用与版本规则

- `status: approved` 后，本文件才是跨页面 UI 规则的唯一事实源。
- `pages/<page-id>.md` 只能补充页面局部设计，不能覆盖本文件。
- 每项稳定规则应使用可引用 ID：`VIS-*`、`LAYOUT-*`、`COMP-*`、`STATE-*`、`INT-*`、`KEY-*`、`CAP-*`。
- 修改规则语义、默认值或兼容行为时提升 `ui-spec-version`，并列出受影响页面。
- 页面 `ui-spec-version` 必须与本文件完全相等，不使用版本范围。全局版本变化后必须检查并更新所有页面，不把兼容性判断留到后续阶段。
- 只有本文件和目标页面文件均为 `approved`、版本完全相等且规则无冲突时，正式交付才完整有效。
- `docs/`、`web/` 和 `assets/` 是研究、推导和评审材料，不自动成为正式设计契约。
- 页面引用的图片和研究材料均为非规范性辅助信息；所有实现要求必须完整写在本文件或目标页面文件中。

## 1. 产品体验与信息层级

待从 `docs/OVERVIEW.md`、`docs/JOURNEY.md` 和 `docs/PRD.md` 汇总已批准的产品级体验原则、用户任务闭环、信息架构及全局优先级。

## 2. 全局 Shell 与布局

待从 `docs/FRAMEWORK.md`、`docs/UX-SPEC.md` 和 `docs/VISUAL.md` 汇总全局区域、层级、Dock、Tab、主内容区、keybar、状态栏、滚动与溢出规则。

## 3. 视觉 Token

待从 `docs/VISUAL.md` 汇总语义颜色、表面、前景、数据色阶、边框、间距、字符、强调配额及禁止项。这里只保留当前有效结论，不收录探索过程和已推翻方案。

## 4. 排版与字符宽度

待汇总等宽排版、数字与单位、对齐、截断、换行，以及 CJK、emoji、Braille display width 规则。

## 5. 通用组件契约

待从 `docs/COMPONENT.md`、`docs/PATTERN.md` 和 `docs/VISUAL.md` 汇总跨页面组件的语义、状态、变体、组合边界与禁用用法。这里只描述可验证的行为契约，不绑定具体实现文件结构。

## 6. 公共状态

待汇总 `default / focused / selected / disabled / loading / loaded / empty / error / failed` 的表现、语义和恢复路径。

## 7. 焦点与交互

待从 `docs/PATTERN.md` 和 `docs/UX-SPEC.md` 汇总全局焦点模型、键盘语义、鼠标等价路径、命令体系、keybar、高风险确认、返回与中断规则。

## 8. 响应式与 Resize

待汇总 160×50、58×32 及中间宽度下的布局切换、区域优先级、隐藏、折叠、滚动、截断和动态 resize 规则。

## 9. 终端能力与降级

待从 `docs/TUI-CAPABILITY.md` 汇总 T0–T5 能力层、SSH、TrueColor、16 色、`NO_COLOR`、Braille 缺失、无鼠标及低带宽环境的降级合同。

## 10. 动效与性能

待汇总允许的状态动效、禁止的装饰动效、重绘边界、viewport 规模、确定性输出和 SSH 性能约束。

## 11. 可访问性

待汇总纯键盘路径、非颜色语义、焦点可见性、文本可读性、终端能力探测和恢复路径。

## 12. 全局禁止项

待汇总裸颜色、页面私有 token、手拼框线、冲突快捷键、仅颜色状态、无降级高能力字符及其他不可接受实现。

## 13. 版本、例外与冲突处理

- 页面声明的 `ui-spec-version` 必须与本文件完全相等。
- 全局版本变化后必须检查所有页面、更新版本声明，并把受影响页面改为 `draft` 直至人工复审。
- 页面不得自行覆盖全局规则。例外只有同时满足以下条件才有效：具有 `EXC-*` ID、登记在下表、状态为 `approved`，并被目标页面明确引用。
- UI 交付与已知技术约束冲突时，必须列出规则、技术约束和影响，交由人工裁决；裁决完成前保持 `draft`。
