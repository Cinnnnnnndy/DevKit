终端也有审美流派

UX 分析回答"界面怎么组织"，视觉分析回答"它长什么样、给人什么气质"。 同样是 TUI，AwesomeTUI 的荧光粗野、Charm 的糖果友好、PTO 的技术克制—— 是三种完全不同的产品人格。Kunpeng DevKit AI 该站在哪里，是一个需要明确回答的问题。

FLOOR 01

为什么视觉要单独分析

前一份竞品分析是 UX 视角——任务流、信息架构、交互模式。但那份分析里有个被跳过的问题：同样的框架结构，用两套视觉做出来是两个产品。

UX 分析回答

面板怎么分？帮助提示放哪？diff 用什么粒度审？窄屏怎么降级？——结构与流程问题。

视觉分析回答

用几种颜色？边框圆不圆？字要不要发光？留白多少？——气质与可信度问题。

为什么现在做

规范已定到组件级，再往下就是视觉落地。而且选错气质的代价很高：工程诊断工具做成糖果色，用户会怀疑它的严肃性。

先纠正一个更大的假设：TUI 的视觉表达力接近简化版 CSS。调研 Lip Gloss 的 API 才发现——它支持渐变（Blend1D() / Blend2D()）、分层合成（Compositor + Layer）、透明度混合（Alpha()）、色彩运算（Darken/Lighten/Complementary）、五种下划线（single/double/curly/dotted/dashed）、超链接、自定义内外边距填充字符（PaddingChar('·')）。而 TUIStudio 的属性面板里甚至有 drop shadow 和 opacity 滑块。

这意味着我此前在 VISUAL.md 里写的"终端无阴影、无 alpha、圆角只有两档"是基于最保守终端的假设——在支持真彩的现代终端 + Lip Gloss/Textual 这类框架下，可用的视觉手段比想象中多得多。纪律仍然要守（因为要降级），但天花板必须重新认识。

FLOOR 03

视觉原子 —— TUI 到底能做多少

由 Lip Gloss 的样式 API 与 TUIStudio 的属性面板反推出的能力边界。结论：比"字符画"多得多，接近一个简化版 CSS。

维度可用手段API / 证据我们用不用
边框样式Normal · Rounded · Thick · Double · Hidden · ASCII · Markdown，且可单边设置BorderStyle() · BorderTop(true)用。直角=固定区，圆角=浮层
颜色深度四层：ANSI 16 / 256 / TrueColor / 自适应明暗LightDark() · Complete()用。自适应档解决 light/dark 主题
色彩运算变暗 · 变亮 · 取补色 · 透明度混合 · 一维/二维渐变Darken/Lighten/Complementary
Alpha() · Blend1D() · Blend2D()		推翻旧假设可用它生成域色阶，不必手写 11 档
文字装饰bold · italic · 五种下划线（single/double/curly/dotted/dashed）· strikethrough · blink · faint · reverse · 超链接UnderlineStyle() · Hyperlink()用。curly underline 标错误（IDE 语义，工程师认）
盒模型padding / margin 四向 + 自定义填充字符PaddingChar('·') · MarginChar('░')慎用。填充字符适合分隔，不适合常规留白
分层合成多图层叠加渲染Compositor + Layer推翻旧假设这正是 P26 AI 标注层的实现路径——标注真的可以是独立图层
布局水平/垂直拼接 · 绝对定位 · 尺寸测量JoinHorizontal/Vertical · Place用
数据渲染Table（边框 + 逐单元格 StyleFunc）· List（Arabic/Alphabet/Roman/Bullet/Tree 五种枚举器）· Tree（Default/Rounded 枚举器，可递归）table.New() · list.New() · tree.Root()用。Tree 枚举器直接对应工程树的缩进引导线
阴影与透明TUIStudio 属性面板含 Drop Shadow 开关与 Opacity 滑块tui.studio 实拍谨慎阴影在终端里是"用字符模拟"，密集布局下会吃掉一整圈空间
两条要回改 VISUAL.md 的结论。
① 渐变可用——Blend1D() 能程序化生成色阶，我们的域色映射（ub-green / l0a-violet / accum-orange / mte-amber 各 800→300）不必手写十几个 hex，可由品牌色与端点算出来，且能保证感知均匀。
② 分层合成可用——P26「AI 标注层」原本只是概念表述（"把判断叠在数据之上"），现在有了字面意义上的实现：Compositor 让标注真的是一个独立 Layer，可以整层开关、整层调透明度。这条把一个设计概念变成了架构决策。
FLOOR 04

皮肤生态 —— 用户已经有偏好了

终端世界有一批事实标准配色，用户往往已经在 vim / tmux / 终端模拟器上统一了一套。TUIStudio 的主题下拉里默认就是 Dracula；k9s / lazygit / btop 都支持换肤。这意味着"强推品牌色"会与用户既有环境打架。

换肤策略：哪些能换，哪些不能
token 类能否换肤理由
表面层级（6 级）可换用户对底色的偏好最强烈，且换了不影响信息解读
前景色阶（4 级）可换跟随表面走；用 LightDark() 自适应即可
品牌 / 焦点色可换但保留默认焦点态是功能而非装饰，换肤时必须保证与表面的对比度仍达 AA
语义色（✓ ⚠ ✕）受限换肤红=错、绿=通过是跨文化共识，可调色相但不能反转语义
域色映射与数据色阶不可换这是最重要的一条：CPU=绿 / NPU=紫 / HBM=橙 是产品级约定，换肤会让"同一个观测对象在不同人屏幕上是不同颜色"，跨人沟通直接失效。热力图的顺序色阶更不能换——感知均匀性是算出来的，随便换会让"哪个更热"读错。
落地形态：提供 --theme dracula|catppuccin|nord|pto，但只作用于表面与前景层；数据可视化色板硬编码在产品里，并在主题文档里显式说明"数据色不随主题变化"。这与 k9s 的做法一致（skin 管 UI 色，资源状态语义色固定）。
FLOOR 05

可直接取用的视觉手法

从五个流派与实拍样本里提炼，按能不能用在工作台常态分三档。

A 档 · 工作台常态可用

反色分段标签——键位 chip、状态徽章（FAILED / SUCCEEDED），比纯文本易扫读一个量级

左侧色轨 + 中性正文——语义靠徽章与轨色，正文不染色，长日志不变噪音

Tree 枚举器缩进线——Lip Gloss tree 原生支持，工程树的标准形态

curly underline 标错——沿用 IDE 语义，工程师零学习成本

点阵分隔线——比实线轻、比留白明确，用于次级分组

程序化色阶（Blend1D）——保证感知均匀，胜过手写 hex

B 档 · 限特定区域

角部裁切标记——仅演示模式画面边界、导出报告页角

抖动像素字标——仅 splash 的 DevKit 字标

点阵尘埃图形——仅 splash（可做鲲鹏芯片轮廓）与宣传页 hero

描边块字——仅 splash 标题

磷光辉光 + 扫描线——仅 splash 的 2 秒，之后立刻关闭

分层合成透明度——AI 标注层可整层调透明，但底层数据必须始终清晰

C 档 · 明确禁用

吉祥物插画——削弱工程可信度，诊断/审查场景尤其致命

大面积渐变底——终端渲染成本高，且降低文字对比度

常驻辉光——长时间阅读疲劳，且在密集表格上产生视觉粘连

整行染色的日志——MobaXterm 的反面案例，颜色失去分层就是噪音

数据区任何装饰——热力图、Trace、diff 上不加特效，一条都不例外

圆角用在固定区域——圆角在本体系里等于"浮起"，滥用会让层级失效

判断口诀

装饰服务于「这是什么产品」的性格表达；
数据服务于「现在发生了什么」的判断。

两者在空间上永不重叠——这条比任何具体参数都重要。

推论：任何一个视觉手法，先问它出现在哪个区域。同一个辉光效果，用在 splash 是加分，用在 Trace 泳道上就是错误。手法本身没有对错，位置才有。

FLOOR 06

工具链与生态

TUIStudio · 可视化 TUI 设计工具

把 TUI 当界面设计对象来做：左侧组件库（Layout: Screen/Box/Grid/Spacer ｜ Input: Text Input/Button/Checkbox/Radio/Select/Toggle ｜ Display: Text/Spinner/Progress Bar ｜ Data: Table/List/Tree ｜ Navigation: Menu/Tabs/Breadcrumb），中间字符网格画布（带尺寸读数 163×57），右侧属性面板（尺寸/坐标/对齐/边框样式与单边控制/圆角/文字与背景色 + 不透明度/粗斜下删/Drop Shadow）。

对我们的意义有两层：① 它的组件分类可直接校验我们的组件清单是否有遗漏（我们缺 Breadcrumb 与 Radio）；② 它证明 TUI 已经有"设计师可参与"的工作流——设计稿不必只能用 ASCII 画，可以像 Figma 一样出。

Charm · Go 生态全家桶

Bubble Tea 框架 · Lip Gloss 样式与布局 · Bubbles 组件 · Huh 表单 · Glamour markdown 渲染 · Wish SSH 应用 · Gum shell 脚本美化 · Glow markdown 阅读 · Mods / Crush AI 终端。

我们选了 Textual（Python），但 Lip Gloss 的样式 API 是最完整的参考——它定义了 TUI 样式该有哪些维度。做 pto.tcss 时应对照它检查我们是否漏了能力（本次就补出了渐变与分层合成两项）。Wish 值得单独留意：把 TUI 直接做成 SSH 服务，与我们"跑在鲲鹏服务器上"的场景高度契合。

AwesomeTUI · 样本库

开源 TUI 应用目录，20+ 分类，可按 star / 更新时间 / 发布排序。用途是持续找同类产品，不是设计规范。但站点自身视觉是粗野荧光派的高完成度样本。

Textual（我们的选择）

TCSS 是 CSS 子集，含变量/选择器/伪类；内置主题系统与模糊命令面板；textual serve 可把同一份代码跑进浏览器。

视觉侧要补的：braille 画布封装（T2）· 热力网格 Widget（T3）· 图形协议探测与降级（T5）。Lip Gloss 的 Blend1D 与 Compositor 对应能力需在 Python 侧自建或找等价库。

FLOOR 07

Kunpeng DevKit AI 的视觉定位

结论：主体站技术克制派，向外逐级放开浓度。不是"选一个流派"，而是按场景分配浓度。

浓度梯度 —— 越靠右越克制
宣传页渐变 · 辉光
像素字标 · 粒子
Splash磷光 · 扫描线
描边块字 · 2 秒
空态 / 成就反色标签
点阵分隔线
工作台常态中性 6 级
单强调色
审查 / 诊断最克制
只有语义色

这条梯度不是妥协，而是把"性格表达"和"决策支持"分配到不同场景。用户在宣传页需要被打动，在审查界面需要被信任——两者要的视觉浓度天然相反。

五条落地准则
#准则来自
1强调色出现频率越低越有力——品牌蓝只用于焦点、进度、当前项，不满屏铺AwesomeTUI 的三色策略反推
2语义靠徽章与轨色，正文保持中性——长日志、长 diff 不整行染色Specify CLI ↔ MobaXterm 正反案例
3圆角 = 浮起——固定区直角，浮层圆角，不可混用Lip Gloss 边框体系 + PTO 层级规则
4数据色不随主题变化——表面与前景可换肤，域色映射硬编码k9s skin 实践 + 跨人沟通需求
5装饰与数据在空间上永不重叠——手法本身没有对错，位置才有本次分析的总纲
一句话定位：Kunpeng DevKit AI 的视觉人格是「一台精密仪器，而不是一张海报」——它在启动那两秒可以有性格，在工作的几小时里必须退到背景里，把注意力全部让给数据和判断。在一个所有 AI 工具都在比谁更炫的时间点，克制本身就是差异化。
