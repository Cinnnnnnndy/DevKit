工作台外壳

python -m devkitai · 160×44

Dock 从顶通到底，品牌标识在它的头部，tab 带缩回主区——所以屏幕上 一条垂直分割贯穿全屏、一条水平分割横贯全屏，两条线各只出现一次。 早先那版是「全宽 appbar → 下面才分左右」，会出现两条起点不同的横向分割，左上角那块区域归属不明。 全宽的只剩 keybar 与状态栏：判据是切换页签会变的东西归页签，不变的归窗口， 所以输入框在主区内、与 tab 同列，跨到 Dock 底下等于在说「这个输入是全窗口的」。 左树里 crypto.c 后面那截橙条是文件风险，走域色阶；profiler 后面的红色 NEW 是红被允许的唯一功能位——它必须是会消失的，否则就不是徽章而是装饰。

降级路径 · 并排看

同一份数据、同一个组件，三档终端能力

这是整套设计里最需要被看到、也最难用文字讲清的一块。上排是同一条 CPU 曲线： T2 用 Braille 点阵，一格 2×4 = 8 倍密度，画出来是真折线；T1 缺 Braille 字形时掉成一行八分块 sparkline；T0 连块字符都不保证时，只剩「当前值 + 峰值」两个数字—— 图没了，但判断依据必须留下。 下排是热力网格：T3 真彩下颜色承载数值、位置承载拓扑；掉到 T1 颜色被抽掉， 强度改由字形 ░▒▓█ 接住——否则一张热力图会退化成一片同样的方块， 那是丢信息而不是降级。AI 标注层那几个 ⚠ 始终占独立一行，不插进单元格之间： 角标插在格后面会把整行往右挤，网格靠位置表达拓扑，一错位这张图就废了。

图元画廊

python -m devkitai gallery · 十四种图表原语

图元不按名字排，按回答什么问题分组——选图之前先问自己在回答哪个问题，选错组的图画得再好看也读不出结论。 三条贯穿全族的规则：八分之一格精度（水平方向也有 ▏▎▍▌▋▊▉█，10 格宽的 bar 因此能分 80 档； 没有它 82% 和 85% 画出来一模一样，而这种数字恰恰是拿来做判断的）· 并置必须共用量程（分别归一化会让每条都填满画布，而并置的全部意义就是比较）· 画不下的要显式说（火焰图那行 1 帧过窄未显示——悄悄丢掉窄帧会让「我看全了」变成错觉， 而给窄帧兜底成 1 格又会让它们集体虚胖、把宽帧挤走）。 注意最上面那组 Metric Bar：bar 走域色阶，只有数值文字转语义色—— 一个 90% 的利用率本身不是错误，把两者刷成一个颜色等于宣布「数值大 = 出事了」。

在本地跑起来

# 它是终端应用，浏览器里跑不了——上面的图是它的真实输出
cd kunpeng-devkit-ai-tui/app && pip install -e '.[dev]'

python -m devkitai            # 工作台外壳
python -m devkitai gallery    # 图元画廊
python -m devkitai preview    # 组件预览页，按 t 现场切换渲染层
pytest                        # 159 个测试

# 强制降级，验证上面那张并排图不是摆拍
DEVKITAI_NO_BRAILLE=1 python -m devkitai   # T2 → T1
NO_COLOR=1            python -m devkitai   # T3 → T1 灰阶
TERM=dumb             python -m devkitai   # 一路到 T0

# 重新导出本页的图
python tools/screenshots.py
