设计系统继承：Web → TUI

直接继承设计系统的 token 体系与设计原则。但 Web 与终端的表达能力差异巨大——本节的核心工作是把 Web 端 token 翻译成终端可实现的 TUI token，而不是简单复制色值。

Web 端终端能力翻译策略
6 级表面 ramp✓ 真彩逐格背景色1:1 直译，truecolor 下完全可复现
4 级前景透明度✗ 无 alpha 通道预合成——按已知表面色离线拍平为实色（见下表）
3 级阴影✗ 无阴影改用边框强度 + 表面步进表达层级
5 级圆角△ 仅两档制表符sm/md → ┌┐└┘；lg/xl/pill → ╭╮╰╯
4px 基准间距△ 单元格非正方拆成 space-x（列）与 space-y（行）双轴
6 级字号 + 2 字族✗ 单一字号，全等宽层级改由 粗细 + 色阶 + 大写字距 + 缩进 编码
5 条数据可视化色阶✓ 真彩1:1 直译，正是热力图/Trace 密度带所需
动效 duration + easing△ 帧驱动换算为帧数（30fps）；保留"动效只服务于功能"原则
继承的第一性原则（原样保留）：中性表面承载布局，强调色传递语义 · 不在 UI 面板背景使用大面积饱和填充 · 高亮色阶仅用于数据可视化 · 每个表面只选一种强调机制，不叠加多种视觉技巧 · 动效只服务于功能，无装饰性循环动画。

品牌色 #0077FF 的两条硬约束。

① 文本不能直接用品牌色。对比度在 #101010 上 4.61:1（勉强过 AA），在 #1C1C1C 上降到 4.12:1，不达标。规范：品牌色只用于填充/边框/焦点底色；文本/链接/图标一律用 --primary-hover #3D98FF（各表面 5.8–6.5:1，全部达标）。

② 与 data-viz 的 copy-blue 撞色。品牌色色相 212°，copy-blue 219°——只差 7°，终端里无法靠尺寸/位置区分，用户分不清"这是 CPU 泳道"还是"这条被选中了"。解决方案见下。

这是 Web→TUI 翻译中最困难的一环。Web 端有 6 级字号 × 3 种字重 × 2 个字族；终端只有一个字号、一个字族。层级必须由其它维度重新编码。

Motion

设计原则原样继承：动效只服务于功能。无装饰性循环动画，无内容区持续播放。这条在 TUI 里比 Web 更重要——终端重绘成本高，且远程 SSH 下每一帧都是带宽。2026-08 收紧：状态一律不靠闪烁表达——原先允许的「Timeline 当前步呼吸」已删除，见下方。

TokenWebTUI @30fps用途
--duration-fast100ms3 帧hover / 选中态切换 / 焦点移动
--duration-base200ms6 帧面板切换 / 分栏展开
--duration-slow350ms10 帧模态浮层进出 / Workspace 切换
允许的动效（服务于功能）：
  ⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏  spinner —— 仅在真实 pending 的工具调用上（逐帧换字符，不是闪烁）
  █░ → ██░ → ███   进度填充 —— 有确定进度时
  逐行 reveal          流式输出

禁止：
  ✗ 状态靠闪烁表达（呼吸 / 闪动 / 忽明忽暗）
  ✗ 常驻装饰性动画（跑马灯、闪烁边框、彩虹渐变）
  ✗ 无进度信息时的假进度条
  ✗ 全屏重绘式转场（远程 SSH 下会明显卡顿）

为什么把「呼吸」也删掉：闪动是「进行中」的第 4 个通道，而前 3 个——颜色、填充（实心 / 空心）、文字（进行中）——已经说清了同一件事；多一路通道不增加信息，只增加噪音。它还在三处直接失真：① 静态帧读不出来（截图、SSH、录屏抽帧里「在跑」和「卡住」长得一样，而这恰恰是最需要区分的两种状态）；② 降级后消失（NO_COLOR / 16 色 / prefers-reduced-motion 下退化成灰色的忽明忽暗，或者干脆不动）；③ 与资源纪律冲突（远程 SSH 下按帧计成本，一个为了「好看」的循环重绘要一直占着带宽）。需要强调「进行中」时，改用常亮的区分手段：实心填充、外发光、条内文字——它们在任何一帧里都一样清楚。状态指示只用一个 9px 方块（见 Status Square），所以这里也不再指望某个字形去接住颜色被抽掉的情况。唯一保留的运动是 Loading 的旋进字形，它换的是字符不是透明度：旋进表达「还在推进」，闪烁只是同一帧的明暗变化，两者不是一回事。

远程降级：检测到高延迟连接（RTT > 80ms）时自动关闭所有过渡动画，只保留 spinner 与进度条，且 spinner 降到 4fps。

三条用色纪律

评审时直接拿来当判据
  • ✓形状层分离，比调色相更可靠。语义色只上字符、短文本与状态方块（⚠ 告警字形、状态标签、9px 状态方块），永不上表面色块；数据色阶只上色块与点阵（█▓▒░ ⣿），永不上文字。状态方块是这条纪律里唯一的色块例外，理由写在 Status Square：它 9px，占位等同一个字，读法是"指示"不是"表面"。有了它，即使 warning 35° 与 accum-orange 25° 色相接近也不会误读。
  • ✕语义色不参与数据可视化。一个 90% 的 CPU 利用率本身不是"错误"——它该用顺序色阶的最亮档，而不是 danger 红。只有当 AI 判定它构成问题时，才由 P26 标注层叠加 danger 色的描边与角标。把"数据"和"结论"用不同的颜色系统表达，是这套规范里最重要的一条用色纪律。
  • ✓强调色配额：蓝 = 当前对象，或当前唯一推荐的动作。其余一律中性。第一版把蓝铺到十几处，结果蓝不再指向任何东西。评审判据：遮住所有蓝色，还能说清"我现在选中的是什么"吗？能，说明蓝铺多了。

对话流基元 —— 跨产品调研统一决策

AI CLI 的主界面本质是一条不断滚动的对话流：用户消息、AI 文本、工具调用、等待状态、Plan、进度、系统提示混排在同一条纵向流里——这条流怎么分行分色，直接决定产品好不好读。下面对比了 OpenCode / Codex CLI / Gemini CLI / Claude Code 四家在 14 类基础元件上的做法，逐条给出 DevKit AI 的统一决策。P01–P20 里的 Agent Timeline、AI Plan、Tool Execution 等场景级 pattern，都是拿下面这些行级基元拼出来的——这里补的是最底层、被复用最多、却从未单列过规范的一层。

本节分四组：对话流基元（14 类）回答「一条流里的这一行是什么」，编排类元件（8 类）回答「这一行由谁产出、有几件事正在同时进行」，输入区单元（4 类）回答「不在流里、但和流同一眼位的那几个东西是什么」，页面级元件（7 类）回答「整页设置与它带来的两枚新标记怎么摆」。后三组随「主 Agent 编排多子 Agent 并发」「会话内改模型 / token 预算」「模型管理与配置」三件事一起新增——一组画的不是一个行而是一棵树怎么在一维滚动的流里落下来；一组压根不在流里；还有一组连对话流那一屏都不在，所以都不塞进上面那张表。

DevKit AI 有两个对话流渲染面：Agent Workspace（Electron/浏览器承载，真实 CSS 渲染，圆角卡片、渐变、模糊都能画）与 kunpeng-devkit-ai-tui（OpenTUI 原生终端，只有字符格）。下面的样式画廊直接用真实 HTML/CSS 卡片渲染——就是 Agent Workspace 的实际样子，不是终端字符画；每张卡末尾标注它在终端面上退回什么形态，两个面共用同一套决策，只是画法不同。

为什么要进对话流，而不是弹 toast、弹窗、或在右上角冒一条：「我什么时候把它改成 85 的」是一个会被追问的问题，答案必须在滚动历史里查得到；toast 三秒后消失，翻历史时它从来没存在过。
被拒也要回执，而且要给出正确写法：静默失败会被读成「我是不是没按对回车」，用户会反复敲同一条命令。拒绝回执必须同时回答三件事——没改（用 状态方块的实心金，和「受阻」同色）、边界/原因是什么（数值范围、名字为什么有歧义、缺哪个配置）、那该怎么敲。四种拒绝理由共用这一个形状：范围越界、名字多义（列出候选的别名与端点）、端点不可用（缺 API_KEY）、无匹配项——不为新理由造新组件。
回执只说业务，产品语义归本页的单元定义：回执的职责是「这次发生了什么、你该怎么改」。所以「告警线是『你想在第几个点被告知』、它是阈值不是水位、超过 100% 等于不提醒自己」这类产品语义不由回执承担（本页上面 Quota Bars 与 Status Bar Metrics 两条已经把阈值 ≠ 水位写清楚了），业务流里只留数值边界与正确写法。判断标准很简单：同一句话换个项目还成不成立——成立的是业务，只跟本产品怎么设计有关的，是标注，标注一律收进本页的单元定义，不混进用户的真实会话。两类最常犯的标注：位置自述——「底栏的 ctx 当前值不变」→「当前用量不变」（数字在哪看是单元的事，回执只报数字本身）；行为自述——「其余可直接切」→ 删（候选列表怎么操作属 Model Switcher 单元，不属这次会话的业务状态）。
两个入口只留一份痕迹：敲完整命令、点模型卡的一行，是同一个动作的两个入口，都要写回执；管理页里点「设为激活」也写同一条结构的回执。只有同一屏内的就地操作不重复写（卡上的 current 标记本身就是它的反馈）。
写入位置在对话流末尾、并自动滚到底：改完立刻看到结果，不用自己往下找；回执只进当前场景的那条流，翻历史不会串场。

列表行与表单的分工（PRD 的硬约束）：点左侧某一行只是把它读进右侧，不改变激活状态；「激活」与「加载」是两个独立操作，各有一个手势、各有各的痕迹——左列方块说的是「谁在用」，右表按钮说的是「改用谁」，左边读、右边写。若右表有未保存的改动就点「设为激活」，先保存再激活，不然改了一半的字段会静默丢掉。
删掉当前激活的模型：自动接管给列表里下一个可用模型，页脚给出结果行；列表被删空则回到缺省态。删除必须二次确认，卡片里写清删的是哪个别名并带上端点——重名条目（两个「私有云」）最容易在这里删错。删掉一个 未激活的模型不该动当前会话的任何东西：它只从列表里消失。

Guidance Chip 缺省态（同一个激活指针的两处派生显示）
① 顶栏提示未配置模型，请通过 /model 命令进行配置　[ 点它等同敲一条 /model ]
② 对话区居中卡需配置模型后方可开始对话　[ 立即配置 ]

两处都是「没有任何模型处于激活状态」这一个指针的派生显示，不是两个独立的开关状态；此外还有三处派生：底栏模型位写「未配置」、提示行模型位留空、左列方块全为未激活。缺省态下顶栏提示可点（它是键盘用户与鼠标用户都能走的那条出路），对话区居中卡给同一件事的第二次机会——一个在页壳上、一个在内容区，滚动位置不同时至少有一个在视野里。

缺省态的定义要写死：它是「没有任何模型处于激活状态」，不是「列表是空的」。配置可以一条不少地躺在列表里、只是没有一条被设为激活——这种状态下系统仍然不可用，所以判据必须挂在激活指针而不是列表长度上（否则「删掉激活模型」与「删掉最后一个模型」会走出两条不同的分支，其中一条没人测过）。缺省态的每一处显示都是同一个指针的派生：顶栏胶囊、对话区引导卡、底栏模型位写「未配置」、提示行模型位留空、左列方块全为未激活——不留任何一处硬编码的「已配置 / 未配置」布尔值，否则改一处就会剩下五处互相矛盾。
缺省态下输入框仍然可聚焦但回车无效（给一条「先配置模型」的回执），不能直接禁用输入框——禁用之后键盘用户连 /model 这条出路都敲不出来，而这条出路恰好是唯一的出路。唯一的自动激活例外：列表里第一条保存成功的配置自动成为激活项（否则「配好了却还显示未配置」是条死路，用户会以为没保存成功）；此后新增的条目一律不自动激活。

本轮新增 → 基元映射（每一部分分别落在哪个对话流基本单元上）

三条贯穿全族的规则

① 八分之一格精度是地基。垂直方向有 ▁▂▃▄▅▆▇█，水平方向同样有一套 ▏▎▍▌▋▊▉█。一个 10 格宽的 bar 因此能表达 80 档而不是 10 档——没有它，82% 和 85% 画出来一模一样，而「兼容性 82%」这种数字恰恰是拿来做判断的。

② 并置的图必须共用量程。多列条形、多系列折线、Before/After、双向面积——分别归一化会让每条都填满画布，看着都一样忙。而并置的全部意义就是比较。

③ 画不下的东西要显式说，不能悄悄省略。排行榜尾部标 … N more，火焰图标 N 帧过窄未显示。悄悄丢掉窄帧会让「我看全了」变成一个错觉，这比不画更危险。同理也不做「最小宽度 1 格」的兜底——那会让窄帧集体虚胖、把宽帧挤走，图就假了。

Metric Bar 的着色 —— 一处规范冲突，已按本文档解
COMPONENT.md v0.2 原写「阈值着色：<60% accent · 60–85% warn · >85% error」，即把语义色刷到 bar 上。但本页 Colors 一节定死语义色只上字符与短文本、永不上色块。冲突按本文档解：
元素走什么色因为它是
bar 本身域色阶顺序取档数据
数值文字 / 前缀符号阈值语义色结论

这不是折中。一个 90% 的 CPU 利用率本身不是错误——只有当它被判定为问题时才该出现语义色。把两者刷成一个颜色，等于宣布「数值大 = 出事了」，而这在性能调优场景里恰恰经常是反的：利用率高往往是好事。

对齐 —— 禁用裸 ljust / rjust

所有图元的标签与表格列必须走 render/text.py 的 fit() / pad() / truncate()。Python 数的是码位，终端排的是单元格，一个汉字占 2 格：f"{'折线':<12}" 实际占 14 格，f"{'Sparkline':<12}" 占 12 格——同一张表里两种标签混用，列就是歪的。这类 bug 只在中文标签下出现，纯英文界面上怎么测都测不出来，所以靠纪律不靠自觉。

为什么用 <pre> 而不是截图。SVG 按「一个字符 = 一个单元格」推进 x 坐标，浏览器里 CJK 字形的实际步进由字体定，于是中文标注全叠在一起。改成 <pre> 由浏览器自己排字，代价是标签列一律 ASCII、中文只许行尾——这条在生成期由断言把着，违反直接报错。

图元尺寸与排布 —— 每种图多大才该画

起因是多图元同屏：一屏上同时挂着 braille 曲线、热力网格、gauge、双向面积、算子表、Trace 泳道，每种图的尺寸若各自临时定，结果就是没人知道某张图在一条 24 列的栏里到底该画还是不该画——「画得下」和「读得出」不是一回事。判决集中在 app/devkitai/layout.py 的纯函数里，不由各个 widget 自己拍。

最小可读尺寸

低于它这张图就不该画，该退成 fallback 那一列写的形态。不是「缩着画」。

推荐尺寸

给得起就给到这个数。多数图元吃到推荐值即停，不摊成长条。

纵横比约束

列÷行的允许区间。越界不是拒画，是把盒子裁到带内再画。

收缩优先级

同屏并置、空间不够时谁先让。按降级损失排，不按重要性排。

格子不是像素 —— 视觉纵横比 = 列 ÷ (2 × 行)

终端字符格的宽高比约 1:2，所以下表里所有比例都是列÷行的原始格子比，换算成眼睛看到的比例要再除以 2。一张 40 列 × 6 行的折线，格子比 6.7，视觉上是 3.3:1 的横长条——按格子数直觉去想比例，会稳定地想扁一倍。

这些数不取 4 的倍数。页面 CSS 的 --grid-unit:4px / --chart-trim 管的是这张网页自身的排版；图元尺寸的单位是字符格，每个数都由图元自己的几何定死——像素数字的 11 列是「3 位 × 3 列 + 2 个间隔」，braille 曲线的 3 行是「12 个点阵行」。把它们凑成 12 和 4 就是把规格编出来，两套网格不该互相对齐。

收缩优先级 —— 按降级损失排，不按重要性排

同屏并置、空间不够时谁先让？答案不是「谁不重要谁让」，而是谁掉一层损失小谁先让。这跟整屏降级里「Console 先让、Canvas 后让」是同一条原则——过程信息让位给结论。同一档内先让推荐面积大的：从大图上收回一样多的格子，代价更小。

档让出的代价图元
① 先让掉成一行数字，结论零损失像素数字 · 分段 · 数图 Stat · 进度 · 水位 · Metric Bar · Sparkline
②掉一层仍在回答同一个问题面积 · 双向面积 · 多列条形 · Before/After
③压缩会丢掉比较能力排行 · 散点 · 折线
④ 最后让形状即信息，压扁等于没画火焰图 · 泳道 Timeline · 热力网格

① 档那七种为什么最先让，一句话：Metric Bar 掉成 84.3% 什么都没丢，像素数字掉成常规数字丢的只是「一眼可见」。④ 档相反——火焰图深度方向不做降采样（§3.7），压扁了栈形就没了；泳道少一行就少一条「谁在等谁」的线索。

设计系统分割方法在 TUI 的四条落地规则

① 嵌套用表面层，不用阴影

外层 background → 面板 surface-1 → 面板内表头/工具条 surface-2 → hover surface-3 → 选中 surface-4。最多嵌两层，第三层改用留白分隔而非再加一层底色。

② 层级用边框强度

同级区域分隔 border-subtle；跨职责区域（Console 与 Canvas 之间）border-default；当前焦点区域整圈升到 border-strong。焦点不靠颜色靠边框强度 + 左侧 ▮ 标记。

③ 圆角只给浮层

框架内所有固定区域用直角 ┌┐└┘（radius-sm/md）；只有浮层、模态、Palette 用圆角 ╭╮╰╯（radius-lg）。圆角在这套体系里等于"浮起"，不能随便用。

④ 留白只取六档

面板内边距 space-4（左右 2 列 / 上下 1 行）；面板之间 space-5（3 列）；大区块 space-6。禁止裸数字 padding——这是设计系统"不使用任意像素值"在 TUI 的对应物。

工程树深层嵌套 —— 超过 3 层怎么办

PROJECT 面板只有 18–28 列（见上方「区域规格」），工程树缩进却没有深度上限——真实仓库里 src/core/modules/http/ 这种 5 层嵌套很常见。逐层缩进画到第 5 层，树线本身就吃掉小半个面板宽度，文件名没地方待——这和 图表单元 那条"画不下的东西要显式说，不能悄悄省略"的纪律撞在一起：工程树画不下深层结构时，也不能悄悄截断文件名了事。

│ │ │ │  ngx_http.c ■

中间路径省略 —— 只留根与当前活跃文件的直系祖先，其余折成一个可展开的 … 
nginx/
├ … 3 层已折叠 · [↵] 展开
│ └ http/
│    ngx_http.c ■
└ conf/

… 不是省略号装饰，是可交互节点——Enter 就地展开成完整中间层，信息不丢，只是先收起来；和 Ranking 的 "… N more"、火焰图的"N 帧过窄未显示"是同一条纪律：画不下就显式说画不下，不能悄悄吞掉。折叠边界跟 ⇄ 跟随 联动——Agent 当前在改的文件，它那条祖先路径自动展开到底；不在这条活跃路径上的深层子树才折叠成 …，用户不用先手动点开五层才看到 Agent 正在碰哪个文件。超过 3 层祖先触发折叠——3 是这里的阈值，不是 5：5 层只是"深层嵌套经常发生"的举例，不是要等用户撑到 5 层折叠才生效。

Demo 故事线

一条连续叙事，供演示串讲。主角：性能工程师，要把一套 x86 上的 nginx 迁到鲲鹏 ARM64 并调到可上线的性能。全程在本地开发机上跑，不连任何远端服务器——打开终端就能开始。

演示环境：纯本地，零前置。Runtime 随二进制本地起，不需要填服务器地址、不需要凭据、不需要网络。devkitai 一敲就进工作台——这是演示的第一个说服点，也是"原生 TUI 单二进制交付"的直接兑现。
幕发生什么观众看到的"哇点"
① 开场本地终端敲 devkitai，全屏工作台直接起来，零配置、零登录。首屏显示环境已就绪 + 检测到 3 项能力未装，一键装好。一条命令进工作台——不用装 IDE、不用配环境、不用连远端
② 提需求直接说"把 ./nginx 迁到鲲鹏"。系统不立刻动手，先出 5 步 Plan 并标注要调哪些工具。AI 先给计划再执行，计划可改
③ 补配置执行到"编译验证"时停下：本地没探测到 aarch64 交叉编译工具链，需要指定路径和输出目录。就地弹层收集（带 Tab 路径补全），填完接着原来那一步继续。不是一开始灌一堆表单，要用到才问，且说明为什么要
