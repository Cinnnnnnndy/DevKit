这不是网页模拟，是 devkitai 真的跑了一遍

下面这段回放，是 React 19 + OpenTUI 0.5.1 编译出的 devkitai 二进制，在一个 160×45 的真实 PTY 里被脚本按键驱动、跑完十幕迁移流程的字符流录像。

录的是字符和 ANSI 转义序列，不是像素 —— 所以它体积只有 124 KB（gzip 后），文字可以选中复制，颜色是原样的 24-bit 真彩，放大也不糊。旁边那些设计稿演示画的是「应该长这样」，这一页是「实际长这样」。

在自己机器上跑

macOS / Linux 都行。只需要 Bun，不需要 Node、不需要装 IDE、不起任何服务。

# 1. 装 Bun（版本锁在 1.3.14）
curl -fsSL https://bun.sh/install | bash

# 2. 装依赖并启动
cd kunpeng-devkit-ai-tui/tui
bun install --frozen-lockfile
bun run dev

# 直接跳到某个界面
bun src/index.tsx --screen=charts       # 图表画廊
bun src/index.tsx --screen=components   # 22 个组件
bun src/index.tsx --screen=patterns     # P01–P26

# 换 Mock 场景 / 关颜色 / 关 Braille
DEVKITAI_MOCK_SCENARIO=slow bun run dev # happy|empty|error|slow|offline|extreme
NO_COLOR=1 bun run dev
DEVKITAI_NO_BRAILLE=1 bun run dev

终端窗口建议拉到 160×45 以上。窄于 80 列会走 narrow 档，Dock 整个隐藏、Console 压到 5 行 —— 那是刻意的降级，不是画崩了。想看降级本身，把窗口慢慢拖窄就能一档档看到它切。

# 质量门禁：格式 + lint + typecheck + 77 个测试
bun run check
✓ 27 render · 34 unit · 7 integration · 9 packaging

这段录像是怎么来的

留个记录，方便下次重录。

用 Python 的 pty.fork() 开一个真 PTY，TIOCSWINSZ 把窗口钉死在 160×45，然后按脚本注入按键，把子进程吐出来的字节流按时间戳存成 asciicast v2。

按键不是按固定秒数发的 —— 那样会在异步 Mock 还在 loading 时把键丢掉（第一次录就是这么翻的车：Build Verify 在两个补丁只批了一个的时候被按下去，直接撞进 仍有补丁未审查 的错误态）。改成等输出安静下来再发下一个键，配一个超时兜底，十幕就一次跑通了。

录制于 160×45 · TERM=xterm-256color · COLORTERM=truecolor · 播放器 asciinema-player 3.8.0（已随仓库自带，不走 CDN）
